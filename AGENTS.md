# AGENTS.md

Guidance for AI coding agents in this repository.

## Project

**Hey Listen** — an audio analysis workbench. Capture, filter, and analyze audio from
files, live inputs (mic / system / process / mix), and fundsp synthesis; save source +
setup + results to one binary `.heyl` project.

```
hey-listen/
├── src/                 SolidJS frontend — shell, timeline, docked charts, graph editors
│   ├── components/      UI by region: timeline, analyzer, annotations, compare, graphEditor, …
│   ├── state/           per-domain stores: project, analyzer, annotations, capture, compare, …
│   ├── lib/             pure helpers: graph spec/layout, formatting, geometry, export, …
│   ├── audio/           preview + transport playback glue
│   ├── bindings/        ts-rs output — GENERATED by `cargo test`, never hand-edit
│   ├── preview/         browser-only shell harness (`preview.html`)
│   ├── styles/          shared CSS
│   └── tests/           vitest unit suites
├── src-tauri/           Rust core — Tauri app and workspace root
│   ├── src/             commands, audio engines, project store, MCP server
│   ├── cli/             `hey-listen-cli` batch binary
│   ├── mcp/             stdio MCP entry
│   ├── tests/           integration tests + shared fixtures
│   └── capabilities/    Tauri permission manifests
├── e2e/                 WebdriverIO specs, support helpers, fixtures
├── docs/                manual/ · development/ · archive/ — see `docs/README.md`
├── scripts/             maid gates, sidecar staging
├── landing/             Astro landing page and the published manual/docs
├── public/              fonts and icons
└── video/               Remotion workspace (separate npm project)
```

Git-ignored output is omitted (`node_modules/`, `dist/`, `src-tauri/target/`,
`src-tauri/binaries/`, `e2e/artifacts/`).

## Workflow

1. **Read the plan.** `docs/development/000_roadmap.md` is the living milestone list;
   read the design note for your area under `docs/development/`. Write new decisions
   there, never in the frozen `docs/archive/`. Product behaviour and layout constraints
   are specified in the roadmap and design notes, with the frozen spec in `docs/archive/`.

2. **Load the matching skill — mandatory, before touching the domain.** The skills
   carry the exact APIs and signatures; never guess them. See the table below.

3. **Deliver one milestone at a time.** Start only when asked; finish and validate it
   before the next.

4. **Make minimal, focused changes** in the existing structure and style.

5. **Validate only the scope that changed.** One command per concern — never re-run the
   same gate. See *Validation* below.

## Validation

Run the narrowest command that covers the change, then stop.

| You changed | Run |
| --- | --- |
| Frontend types or logic | `npm run typecheck`; a pure helper also gets `npm run test:unit -- src/tests/<suite>.test.ts` |
| Rust logic | `cargo check` in `src-tauri/`; add a filtered `cargo test -p <crate> <filter>` for the touched tests |
| A boundary type (IPC / project) | `cargo test` — it regenerates `src/bindings/`; commit the result |
| UI, layout or CSS only | `npm run dev`, then `http://localhost:1420/preview.html`; no cargo |
| Landing, manual pages, roadmap, acknowledgements | `npm run check:landing`; `npm run build:landing` |
| E2E-visible behaviour | `npm run test:e2e -- --spec e2e/specs/<file>.spec.ts` |
| Lint / format / dup / size | the matching `maid:*` script; full `npm run maid` once before handing off |

- **Fresh checkout:** run `npm run sidecar` once before any `cargo` command — Tauri
  resolves `bundle.externalBin` on every cargo invocation, not just `tauri build`.
- Run `npm run build` only when the bundle itself matters; a missing `dist/` blocks
  `cargo check`.
- Say exactly what you ran and what it reported.

## Hard rules (project etiquette)

- **Keep the maid green.** Source files stay under 400 lines — the budget in
  `scripts/maid-baseline/fileSizes.json` only ratchets down, so split a file rather than
  raise it. No duplication, no dead code, both languages formatted.
- **No copied blocks.** A second copy means extracting it: shared Rust fixtures →
  `src-tauri/tests/support/*.rs`, shared derive lists → one `macro_rules!`, chart-image
  registration → `components/analyzer/chartImage.ts`, a shared uPlot stack →
  `CompareTimeChart.tsx`, graph tab chrome → `GraphTabChrome.tsx`, WebdriverIO hooks →
  `e2e/support/session.ts`, node param tables → a row builder (see `reverb.rs`), shared
  CSS → `src/styles/shared.css`. The clone gate is a ratchet: fix the clone and lower
  `threshold` in `.jscpd.json` in the same change.
- **One list, one place.** Pick the owner (an enum, a doc, a type) and have everything
  else link or import it — `e2e/support/tools.ts` imports `AnalyzerId` and `AnalyzerView`
  rather than restating them. When two surfaces must agree, add a test instead of a
  comment. **Counts are never prose:** write "every analyzer in `AnalyzerId`", not
  "29 tools".
- **Typed ids, not strings.** Parse an id once at the boundary (serde/IPC, CLI or MCP
  args, a project load, a URL), then carry the enum everywhere internal. Extend the
  existing enums (`AnalyzerId`/`ToolId`, `Family`, `Section`, `SourceKind`, `CaptureKind`,
  `CaptureEventKind`, `WindowKind`, `MenuAction`, `ThemeBase`/`ThemeMode`, `BatchCommand`)
  — never add a parallel `String`. A new id domain is one enum with `strum` + `serde` +
  `ts_rs::TS`: identical serde/strum spelling, string encoding across `postcard`, and a
  round-trip test. Regenerate `src/bindings/` with `cargo test`; never hand-edit it.
- **Name the vocabulary precisely.** Four "kind" axes: `Section` (sidebar grouping),
  `AnalyzerView.kind` (frontend renderer), `Family` (Rust result shape),
  `CompareViewFamily` (compare dispatch) — read their values from the types, do not
  restate them here. **Annotation** is what the user writes; **a note is musical** (only
  the `noteMetrics` segments). Never bulk-rename a word across the tree. Display copy says
  "annotation"; rename its test id in `e2e/support/selectors.ts` in the same change.
  `WindowKind` is ours, `WindowFn` is oxiaudio's; qualify `flexaudio::SourceKind`;
  `SourceData` is our PCM buffer.

## Local notes

- **npm cache:** `~/.npm` may hold root-owned files and throw `EPERM`. Use
  `npm_config_cache=…/.npm-cache npm install …` (gitignored), or fix it once with
  `sudo chown -R 501:20 ~/.npm`.
