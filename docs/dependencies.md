## License notes

- **Attribution surfaces.** The in-app **About** dialog lists the required
  attributions (`src/lib/attributions.ts`), and `ACKNOWLEDGEMENTS.md` (generated by
  the `acknowledgements-rs` CLI) thanks the individual contributors. Keep both in step
  with the dependency tables above when a dependency is added or removed.
- **Font Awesome Free 7** (the icon font) is **vendored**, not an npm dependency:
  only `FontAwesome7Free-Solid-900.otf` + its `LICENSE.txt` ship, under
  `public/fonts/fontawesome/`. Its three licenses require **attribution**, which the
  in-app About dialog provides (`src/lib/attributions.ts`). Do not remove the embedded
  font-file comments or the bundled license text.
- **symphonia is MPL-2.0** (file-level copyleft): fine to link against; any
  *modified* symphonia source files must be published under MPL-2.0. No planned
  modifications.
- **oxiaudio** `pure` feature set is Apache-2.0; MP3 **encode** is excluded from
  the facade (separate LGPL crate) — not used.
- Confirm exact `flexaudio` / `fundsp` license strings from their `Cargo.toml`
  before any redistribution.

## MSRV

Core crates require Rust ≥ 1.85 (`flexaudio`, `symphonia`); `tauri-plugin-cli` and
`tauri-plugin-clipboard-manager` require ≥ 1.90. Toolchain in use: 1.99.

## Tooling notes

- **Prefer the npm CLI** (`npm run tauri dev` / `npm run tauri build`) over a
  `cargo install`ed `cargo tauri`. The two can drift apart: the npm CLI tracks
  `@tauri-apps/cli` (2.12.x) while a cargo-installed `tauri-cli` may be older
  (e.g. 2.8.4). An older CLI validates `tauri.conf.json` against *its own* older
  schema and rejects newer keys (e.g. `bundle > macOS > infoPlist`) even though
  `tauri` crate accepts them. If you must use `cargo tauri`, keep it in step:
  `cargo install tauri-cli --version 2.12.1`.
- **Release / packaging (M7):** bundle with `npm run tauri build`; add GitHub
  release workflows and a build matrix covering the supported platforms.
- **Type exchange (ts-rs):** the structured IPC types are defined once in Rust with
  `#[derive(ts_rs::TS)]` + `#[ts(export)]`. `cargo test` regenerates their TypeScript
  definitions into `src/bindings/` (configured by `src-tauri/.cargo/config.toml`,
  `TS_RS_LARGE_INT = "number"`), and the frontend imports them — so the two sides
  cannot drift. Run `cargo test` after changing a boundary type.
- **MCP server (M9):** the loopback MCP server uses only `std::net` + `serde_json` +
  the Tauri event/command surface. The follow-up adds `tauri-plugin-cli` (the app
  binary's `--mcp` / `--headless` flags), `tauri-plugin-store` (the persisted MCP
  settings) and `tauri-plugin-clipboard-manager` (the popover's Copy). The
  `heylisten-mcp` binary is a second binary in the same crate — a plain console
  program (no GUI), so it can run headless. On macOS the follow-up also depends on
  `objc2` / `objc2-foundation` (already in the tree via Tauri) for the App Nap
  opt-out, both in the bundle's `Info.plist` and at runtime. See [`mcp.md`](mcp.md).
- **Batch CLI (M10):** a **subcommand of the app binary**, declared in the existing
  `tauri-plugin-cli` (`plugins.cli`) — no new crate, no new binary. It reuses the
  headless session (`mcp/dispatch.rs`) and the same engine functions, so it adds no
  dependencies. See [`cli.md`](cli.md).
